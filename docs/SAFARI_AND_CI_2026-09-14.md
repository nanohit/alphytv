# Safari / первый запуск Lift и ошибки CI — 14 сентября 2026

Пользователь сообщил о долгом первом открытии «Люди Икс: Последняя битва» в Safari на macOS и iOS, затем о нормальной скорости. Полного воспроизведения на этих устройствах у нас нет; HTTP-запрос с Safari User-Agent не является проверкой Safari.

## Что установлено

- В индексной записи `id=299`, `lyudi-iks-3-poslednyaya-bitva` отсутствовали embed/KP. Живой `/titles/resolve` ответил за 929 мс и сохранил `embed_id=314`, `kp=61361`.
- Четыре Lift info relay ответили HTTP 200: первые проверочные запросы 544–586 мс, повторные 384–517 мс. Холодное состояние серверов не контролировалось. У GZW по-прежнему старый Cache-Control 6 ч; клиент revalidates info после собственного TTL.
- Для конкретного фильма info: 859 мс. Страница плеера с Origin:null и заголовками Safari: HTTP 200, есть makePlayer, DASH и HLS; 611 мс и 70 мс. Это сетевые проверки из одной точки, не измерение первого кадра на Mac/iPhone.
- Последовательные попытки signed/bare embed могли задержать запуск relay на 18 секунд. Сбой первичной загрузки media iframe оставлял отвергнутый ready Promise до перезагрузки вкладки. Подсказка открывалась только по mousedown, а blur закрывал список через 120 мс.
- [CI 34842671134](https://github.com/nanohit/alphytv/actions/runs/34842671134): полный обход завершён, 28 fill успешно, 7 ошибочных, остановка после пяти ошибок. У «Непризнания», «Моей свекрови — монстра», «Октоберфеста 1905» первый API-ответ содержит метаданные, необязательный запрос season=1 — пустой view; он ошибочно заменял карточку.
- [CI 34811491051](https://github.com/nanohit/alphytv/actions/runs/34811491051): `/catalog` вернул 502 Gateway Timeout. [Identity 34820891669](https://github.com/nanohit/alphytv/actions/runs/34820891669): однократный 503 загрузки snapshot, без повтора.

## Исправления

- Lift info и embed получают один резервный путь через 1,8 с ожидания либо после отказа основного. Быстрый ответ не запускает резерв; проигравшая ветвь отменяется вместе с fetch/iframe. Внешнее видео по-прежнему не идёт через наши серверы. Изолированный браузерный запрос сохраняет Origin:null.
- Отказавший при запуске media iframe удаляется, следующая попытка создаёт новый. Таймаут Lift HTTP включает чтение тела ответа.
- Подсказки используют pointerdown/pointerup, click для клавиатуры и fallback для старых браузеров. Один жест открывает один раз; прокрутка не открывает тайтл. Наведение/фокус/касание прогревают известный Lift ID в рамках существующего бюджета. Ответ `/resolve` передаёт уже найденные KP/type дальше, не теряя привязку.
- Пустой необязательный сезон сохраняет первоначальные метаданные; тип сериала учитывается даже без video/season. Настоящие ошибки источника по-прежнему останавливают серию после пяти отказов и теперь указывают slug/reason.
- Идемпотентные запросы каталога и состояния повторяются до трёх раз при сетевом сбое или 502/503/504. Неидемпотентный `/fill` автоматически не повторяется. Снимок identity также получает ограниченный повтор.
- Публикация поиска запускается и после частично неудачного sync, чтобы уже записанные новинки не ждали следующего cron. Сам sync продолжает сообщать настоящие ошибки.

Проверки: **374/374**. Есть отдельные проверки быстрого основного ответа без резервного запроса, зависшего основного ответа с отменой, полного отказа обеих ветвей, touch/click без дубля, прокрутки, восстановления iframe, пустого сезона и безопасных повторов записи.

## Прогрев и ограничения

Общий metadata prewarm уже работает. Постоянные health-пинги не гарантируют отсутствие холодных запусков: Deno может остановить экземпляр даже при трафике и запустить другой регион/экземпляр. Его документированный idle timeout — 5 секунд–10 минут. Данные в постоянном кэше переживают остановку процесса; память экземпляра — нет. См. [Deno runtime](https://docs.deno.com/deploy/reference/runtime/).

Новые аккаунты/ключи не требуются для этих исправлений. Они не превращают сетевые проверки в доказательство 10k DAU или отсутствия сбоев на всех Safari. Обновление версии Shaka, принудительное снижение качества и перенос видео на сервер не выполнялись.

CF status при проверке: 64 825 с KP, 64 690 с player, 16 877 ещё в очереди; свежий тик, ноль последовательных ошибок, 8 записей ждут публикации. Старый полный перечень CF — 81 702; свежие добавления поступают через GitHub sync. CF trigger оставлен включённым.
